# Décisions

| Date | Décision | Alternative envisagée | Raison |
|---|---|---|---|
| 2026-08-25 | Rendements via Eurostat `apro_cpshr` (NUTS 1 Wallonie + 5 provinces), source nationale = Statbel | Télécharger les Excel Statbel / fiches EAW | Les pages Statbel sont protégées par captcha et les noms de fichiers changent chaque année ; Eurostat redistribue les mêmes chiffres officiels en TSV stable. L'EAW reste une source narrative, pas un extract brut. |
| 2026-08-25 | Climat via Open-Meteo Archive (ERA5), 5 points provinciaux, moyenne simple = Wallonie | Copernicus CDS (`cdsapi` + NetCDF) | Pas de compte ni de raster ; ERA5 reste la réanalyse de référence. CDS pourra être ajouté plus tard si un compte est disponible. |
| 2026-08-25 | Imputer BE3 par la somme des provinces si le rendement sort des bornes agronomiques | Laisser les valeurs officielles telles quelles | Rupture d'unité documentée (froment wallon 2011 à 1,17 kt au lieu d'environ 1 100 kt) alors que les provinces sont cohérentes. |
| 2026-08-25 | Saison de végétation = avril–septembre | Année civile seule, ou calendrier par culture | Compromis unique pour comparer les cultures à ce stade ; un calendrier cultural pourra affiner l'analyse (feature 3). |
| 2026-08-25 | Dépendances : pandas, requests, truststore | openpyxl, cdsapi, xarray, PyYAML | Suffisant pour TSV/JSON ; config en dataclasses. `truststore` aligne TLS sur les certificats Windows (certifi échoue souvent derrière un proxy). |
| 2026-08-25 | Jointure interne (`geo`, `year`) rendements × climat annuel | Jointure à gauche (garder les années orphelines) | L'analyse ne porte que sur les couples complets ; Eurostat et ERA5 se recouvrent déjà sur 2000–2024. |
| 2026-08-25 | Anomalies et z-scores climatiques par `geo`, référence = moyenne de la série (2000–2024) | Référence 1991–2020 OMM, ou anomalies wallonnes seules | Cohérent avec la période de rendements ; une normale OMM plus longue demanderait d'étendre le téléchargement ERA5 sans gain pour la jointure. |
| 2026-08-25 | Export CSV **et** Parquet (`rendements_climat`) | CSV seul | Parquet reste fidèle aux types (bool `imputed`, floats) ; CSV reste lisible sans `pyarrow`. |
| 2026-08-25 | Pas de scénarios CMIP6 / SSP dans le jeu consolidé | Ajouter l'API Climate Open-Meteo (GCM downscalés) dès la Feature 2 | Question différente : sensibilité **observée** vs impacts **futurs**. Les rendements n'existent pas en 2050 — il faudrait d'abord un modèle (Feature 6) puis le forcer avec un scénario. Les GCM restent grossiers (même downscalés), multiplient l'incertitude, et mélangeraient observation et simulation dans la même EDA. Piste retenue pour plus tard : Feature 9 optionnelle, **après** le ML basique, en overlay clairement étiqueté « projection », jamais mélangé aux années 2000–2024. |
| 2026-08-25 | Détrendre le rendement (OLS année → t/ha) avant de corréler au climat | Corréler le rendement brut, ou un z-score sans tendance | Le progrès génétique / technique fait souvent monter les rendements ; sans détrend, une tendance climatique se confond avec ce progrès. |
| 2026-08-25 | Spearman comme indicateur principal (Pearson en contrôle) | Pearson seul, ou régression multiple d'emblée | Spearman est plus robuste aux années extrêmes ; n est petit (14–25). Une régression multiple viendra éventuellement en Feature 6. |
| 2026-08-25 | Classement et années atypiques d'abord en Wallonie (BE3) ; provinces en contrôle de signe | Pooler les cinq provinces pour gagner de la puissance | Les provinces ne sont pas des tirages indépendants (même année, climat proche). Pooler gonflerait n et les p-values. |
| 2026-08-25 | Année atypique = résidu z ≤ −1 **et** au moins un \|z\| climatique de saison ≥ 1 | Seulement les pires rendements, ou seulement les années climatiques extrêmes | Le brief demande les cultures **et** les années à risque : le filtre joint évite de labelliser un creux technique ou une année extrême sans impact visible sur le rendement. |
| 2026-08-25 | Zoom froment et épeautre (C1110) | Betterave, pomme de terre, ou culture au \|ρ\| max | Culture phare, série longue (~24 ans), déjà utilisée dans l'EDA. |
| 2026-08-29 | Figures README en anglais dans `pictures/readme/` ; matplotlib déjà dans la stack | Plotly / un dossier `figures/` à la racine | Le README public est en anglais ; les PNG d'analyse (`pictures/experiments/`) restent en français pour `docs/analyse.md`. Pas de nouvelle dépendance. |
| 2026-08-29 | Carte au **NUTS 2 (provinces)** ; choroplèthe matplotlib + GeoJSON GISCO | Arrondissements, Folium, Plotly, GeoPandas | Les rendements n'existent qu'à NUTS 1–2. Matplotlib est déjà là ; Folium/Plotly serviront au dashboard (Feature 7) sans alourdir le rapport statique. GeoJSON filtré dans `data/processed/` pour réemploi. |
| 2026-08-29 | Cible ML = **résidu** de rendement (t/ha), Wallonie, pas de pooling provincial | Rendement brut ; pooler les 5 provinces pour gonfler n | Même logique qu'en Feature 3 : le progrès agronomique n'est pas du climat ; les provinces ne sont pas indépendantes. |
| 2026-08-29 | Régression linéaire scikit-learn + leave-one-year-out ; MAE vs naïve (prédire 0) | Forêt aléatoire / XGBoost ; split aléatoire 80/20 ; MLflow | n ≈ 14–25 : un modèle flexible overfit ; un test de 3–5 années est bruyant. La MAE en t/ha se compare à l'analyse Spearman. Pas de suivi d'expériences pour une seule baseline. |
| 2026-08-29 | Comparer le modèle à 3 variables à la **meilleure univariée** (et publier les VIF) | Multivariate seule | ET0 et température de saison sont collinéaires (VIF ET0 ≈ 4). Sans le contrôle univarié, on attribuerait au « climat » une perf que la pluie seule explique déjà. |
| 2026-08-29 | Dashboard **Streamlit** + **Plotly** ; UI en français | Dash, Gradio, Folium | Stack Python déjà connue ; Plotly pour les séries et la choroplèthe (GeoJSON NUTS 2). Folium n'apporte rien de plus ici. L'app appelle `src/`, sans dupliquer l'analyse. |
| 2026-08-29 | Classement Spearman du dashboard = **série entière** Wallonie, pas la sous-période filtrée | Recalculer Spearman sur le slider d'années | Un palmarès sur 5 ans serait bruyant et suggérerait une « vérité » instable. Le filtre ne s'applique qu'aux séries et aux années atypiques. |
